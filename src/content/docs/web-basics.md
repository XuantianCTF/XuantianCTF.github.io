## Web 安全入门

这一篇是给完全没接触过 Web 安全的人看的。如果你连 HTTP 是什么都不知道，从这里开始就对了。

### 网页是怎么来的

你在浏览器输入一个网址，回车，页面就出来了。这中间发生的事可以简化成两步：

1. 浏览器向某个服务器发了一个请求
2. 服务器把网页内容发回来，浏览器把它画出来

服务器就是一台一直开着、专门等人来访问的电脑。它放着网页文件，收到请求后把对应内容返回。你和它说话用的语言就是 HTTP。

### HTTP 是啥

HTTP（HyperText Transfer Protocol，超文本传输协议）是浏览器和服务器之间约定的沟通格式。它就是一问一答：

- 浏览器发出去的叫请求（Request）
- 服务器回的叫响应（Response）

请求里带着方法和地址。最常见的两个方法：

- GET：要东西，比如打开一个页面、查一条数据
- POST：交东西，比如提交表单、上传文件

一次完整的请求大致长这样：

```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Cookie: session=abc123
```

服务器回的内容长这样：

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html><body>你好</body></html>
```

状态码是响应里第一个数字，记住三个就够用：

- 200：一切正常
- 404：页面不存在
- 500：服务器自己出错了

### URL 长什么样

一个 URL 分成几段：

```
https://example.com:8080/path/page?id=1#top
│      │              │      │        │    │
协议    域名            端口    路径    参数   锚点
```

- 协议：http 或 https，https 是加密过的
- 域名：服务器的名字
- 端口：服务器上的门牌号，默认 80
- 路径：要哪个资源
- 参数：跟着 ? 后面，key=value 的形式，多个用 & 连

这里有个对安全很重要的事：**参数是用户能改的**。攻击者把 id=1 改成 id=2，服务器可能就返回了别人的数据。很多 Web 漏洞都从这里开始。

### Cookie 和 Session

HTTP 本身不记状态。服务器回完你，就忘了你是谁。可网站要记住登录状态，怎么办？

办法是给浏览器发一个小牌子，叫 Cookie。下次请求时浏览器自动带上它，服务器一看牌子就知道你是谁。Session 是同一件事的服务端版本：真正的内容存在服务器上，Cookie 只放一个编号。

从安全角度，Cookie 值得警惕，因为它是跟着请求走的。如果攻击者拿到了你的 Cookie，他就可以冒充你，不需要知道你的密码。这也就是后面 XSS 那篇里为什么要防着别人偷 Cookie。

### 前端和后端

一个网站分两块：

- 前端：浏览器里跑的东西，HTML 管结构，CSS 管长相，JavaScript 管行为
- 后端：服务器上跑的东西，接收请求、查数据库、返回结果

新手容易只盯着前端看，但 Web 安全的大头在后端。前端能看到的代码、能改的按钮，都是给用户看的。真正的判断逻辑，比如你有没有权限、密码对不对，应该放在服务器上。如果后端信任了不该信任的输入，漏洞就来了。

### 漏洞是怎么产生的

Web 漏洞千奇百怪，但绝大多数能归到一个原因：**该验证的输入没验证**。网站把用户给的东西直接拼进 SQL、直接塞进页面、直接当文件名用，于是：

| 把输入用在哪 | 得到什么漏洞 |
|--------------|--------------|
| 拼进数据库查询 | SQL 注入 |
| 直接输出到页面 | XSS |
| 当成上传文件名 | 文件上传漏洞 |
| 拼进系统命令 | 命令注入 |

这几类就是 Web 方向最常见的入门考点，本目录下面都有对应的详细文章：

### 新手要准备的工具

- **浏览器开发者工具**：按 F12 打开，网络面板能看到每一次请求和响应，改前端代码、看参数都在这里
- **curl**：命令行发 HTTP 请求，测试接口很方便
- **Burp Suite**：Web 安全里最重要的工具，可以抓包、改包、重放请求，入门先用免费版就够

```bash
curl -v http://example.com/index.html
curl -X POST http://example.com/login -d "username=admin&password=123"
```
